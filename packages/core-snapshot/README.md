# @minder/core-snapshot

Local file transactions for ordinary files in selected, existing directories. Requires Node.js 22.19 or later. A single writer coordinates transactions across cooperating processes using the same private state directory.

```ts
import { openSnapshot } from "@minder/core-snapshot";

const manager = await openSnapshot({
  stateDir: "/home/alex/.minder/snapshot",
  roots: ["/home/alex/Documents"]
});
try {
  const tx = await manager.begin("Prepare meeting notes");
  await tx.write("meeting.md", "# Agenda\n");
  const result = await tx.commit();
  console.log(result.files[0]?.patch);
  await manager.undo(result.id);
} finally {
  manager.close();
}
```

## Reading, writing and review

`tx.read` returns a Buffer from the current staged view. `tx.write`, `tx.remove` and `tx.move` stage changes. `commit` checks original contents and mode, publishes the transaction and returns its File Diff. `abort` discards staged edits. Relative paths resolve against the first root. Parent directories must already exist. Inspect committed work with `manager.list()` and `manager.diff(id)`. Any untrusted file contents displayed in a terminal should be escaped by the UI.

The snapshot store keeps SHA-256-addressed immutable contents and a durable SQLite journal. Source capture prefers copy-on-write on supported volumes and otherwise makes an independent copy. Repeated identical contents reuse a single object. The original and generated bytes count towards the size budget. Text diffs have time and display-size limits; large or binary changes show sizes and digests.

## Recovery and limits

Commits and one-click undo preflight every path, then replace ordinary files through same-directory renames. Other programs may observe intermediate states across multiple files. If the host process stops partway, opening the store resumes the recorded direction; external edits produce a conflict. Eligible POSIX filesystems additionally synchronize parent directories. Directory synchronization is unavailable in the native Windows implementation. The recovery guarantee covers process termination. Filesystem, hardware and OS write-cache behavior determine power-loss durability.

The manager snapshots file bytes and basic permission bits. Directory trees, hard-link groups, symbolic links, special files and privileged metadata such as ACLs, xattrs and alternate data streams are outside this interface. Roots must be on trusted local storage. External programs concurrently replacing pathname ancestors or writing through shell commands are outside the transaction boundary. Configure host tool access accordingly.

By default files larger than 500,000,000 bytes require a separate irreversible operation. `irreversibleWrite` and `irreversibleRemove` take a human-facing asynchronous confirmation callback and recheck metadata after approval. Use a trusted host interaction for that callback. Ordinary writes remain blocked. The private database retains exception metadata independent of the reversible history.

The default retention period is seven days and the object budget is 5,000,000,000 logical bytes. GC runs during admission and staging, and can also be invoked with `manager.gc()`. Old completed history is eligible for eviction; in-progress work is protected. Keep the state directory private, on a trustworthy volume, and reuse the same protected roots across application restarts.
